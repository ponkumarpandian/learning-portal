# Explainer visuals and scenes (SPEC §7.4, §7.5, Appendix C)

> **Status:** Phase 2 built the player (`src/explainers/`, `src/features/video/`) and `ParticleBox`, `LightRay` and `NumberLine`; the Maths Ch 5 import added `FractionBar` and the Biology Ch 4 import added `DigestiveJourney`. The other 23 visuals come in Phase 7, or when a real chapter needs them (a scene whose visual has no component yet shows a friendly "picture coming soon" stage, and the captions still play).

## 1. Scene JSON (works today: schema + validator)

The schema is `ExplainerSchema` / `SceneSchema` in `src/content/schemas.ts`. Copy `../import-chapter/explainer-template.json` (it passes the validator). Real samples are in `content/explainers/states-of-matter.json` and `content/explainers/light-straight-line.json`.

```jsonc
{
  "id": "kebab-id",
  "subject": "physics",
  "title": "…",
  "sample": true /* seed only */,
  "source": { "pages": [61] }, // optional: one source for every scene
  "scenes": [
    {
      "visual": "LightRay", // must be in VISUAL_NAMES (all 28 §7.5 names)
      "props": { "scene": "torch", "beam": false }, // free-form: the visual defines them
      "steps": [{ "at": 2, "props": { "beam": true } }], // seconds after the scene starts; merged over props
      "narration": "…",
      "captions": "…optional, defaults to the narration",
      "minDuration": 8, // scene length = max(narration time, minDuration)
      "checkpoint": { "questionId": "kebab-id-cp1" }, // asked at the END of the scene
      "source": { "pages": [61] },
    },
  ], // required on real (non-sample) explainers, per scene or at the top
  "questions": [/* Question objects, usually the checkpoint questions */],
}
```

Validator rules (`npm run validate-content`):

| Rule                                                                                                 | Level   |
| ---------------------------------------------------------------------------------------------------- | ------- |
| `visual` must be in `VISUAL_NAMES`                                                                   | error   |
| a checkpoint `questionId` must be one of the explainer's own questions, or any question anywhere     | error   |
| a non-sample explainer needs a `source` on every scene and question (or a top-level `source`)        | error   |
| `subject` must exist                                                                                 | error   |
| ids must be unique across all content                                                                | error   |
| 0 checkpoints, or more than 3                                                                        | warning |
| longer than about 8 minutes (`estimateExplainerSeconds`: per scene, max(`minDuration`, words ÷ 2.3)) | warning |
| `videoRef` on an explainer question (it is ignored)                                                  | warning |

- A lesson uses an explainer with `{ "role": "primary", "kind": "explainer", "explainerId": "…" }`.
- A question jumps to a scene with `"videoRef": { "video": "primary", "scene": N }`, where **N is 0-based**.
- Narration: short sentences in the book's own terms, kid-friendly, with no facts beyond the source pages (see `import-chapter`).

## 3. Building a visual component (the contract to keep)

- **Location:** `src/explainers/visuals/<VisualName>.tsx`, registered in a `src/explainers/visuals/index.ts` map (`VISUALS: Partial<Record<VisualName, ComponentType<VisualProps>>>`). Props: `{ props, subjectId?, reduced }` (`visuals/types.ts`). Shared CSS: `visuals/visuals.css` (`pb-`, `lr-`, `nl-`, `vis-chip`). Put pure geometry in a `.ts` file next to it (see `visuals/particles/`) so it can be unit-tested and react-refresh stays happy.
- **Props-driven SVG:** the component draws a still image from `props` (scene props with the current step's props merged on top). It holds no timers and doesn't fetch anything, so it works offline.
- **Responsive:** use a `viewBox` with `width: 100%`, and no fixed pixel sizes. Keep text in the SVG at `--fs-body` or larger, and use real `<text>` that a screen reader can reach, or `aria-hidden` plus captions.
- **Colours:** use only tokens. The subject colour comes from `subjectVars(subject)` → `var(--s)` / `var(--sd)` / `var(--on-s)`. Use `--ink`, `--surface`, `--line`, `--gold` and `--catch` for everything else. It must look right in all 3 worlds, light and dark.
- **Motion:** animate between step states with framer-motion. When the `reduced` prop is true (the player passes `useReducedMotion()`), **jump to each step's end state** (still frames, step by step), with no tweening, pulsing or looping.
- **Tests:** render each prop/step combination (`@testing-library/react`), check that it doesn't crash, and check the key labels.
- **Visual check:** add it to the `/kit` gallery, then screenshot it (see the `kid-ui` skill).

## 4. Player (built in Phase 2)

Files: `src/explainers/timeline.ts` (pure reducer + helpers, fully tested) · `useExplainerTimeline.ts` (drives it: 200 ms tick, narrator, tab-hidden pause) · `speech.ts` (`Narrator`, `browserNarrator()`, `silentNarrator`, `splitSentences`, `pickVoice`) · `ExplainerPlayer.tsx` · `visuals/index.ts` (`VISUALS`) · `ExplainerKit.tsx` (/kit gallery of every content frame). Curated video + shared UI: `src/features/video/` (`LessonVideo`, `YouTubePlayer`, `Mp4Player`, `CuratedFrame`, `VideoControls`, `CheckpointPanel`, `sources.ts` → `planSources`, `findQuestion`).

- **Timing:** a scene lasts max(narration end, `minDuration`), then moves on. Narrated: the narrator speaks one sentence at a time (rate 0.95 × speed) and each `onEnd` moves the caption on; a voice that never ends is cut off at 2 × the estimate + 5 s. Captions only (no en voice, or `settings.narration` false): the caption follows the `estimateSceneSeconds` estimate, shared by word count. Speed 0.75 / 1 / 1.25 scales scene time.
- **Steps:** props = scene props + every step with `at` ≤ elapsed (in `at` order). The visual is keyed by `scene.visual`, so one instance lives across steps _and_ across consecutive scenes with the same visual: write the next scene's `props` as the previous end state plus an `at: 0` step to animate a change (states-of-matter does this for melting/boiling).
- **Checkpoints:** at the end of a scene with `checkpoint`, the question (explainer's own `questions`, else any content question) replaces the picture: `AskQuestion` mode `checkpoint`, `compact`. "Watch that part again" replays the scene from 0 and asks again at its end; Continue goes to the next scene. Full screen is left first (the feedback sheet is portalled to `<body>`). Checkpoints skipped by tapping ahead are asked after the last scene; "watched" (`onEnded` / `onWatched`) means every checkpoint answered; `checkpointsAllCorrect` = all right without the answer being revealed. A missing question never blocks.
- **Controls:** ⏪ Back 10 s (crosses into the previous scene) · ▶/⏸ 76px · 💬 Captions (on by default, 1.25rem, under the picture so nothing is covered) · ⛶ Full screen (Fullscreen API on the frame, CSS full-window fallback) · Speed segmented control · a track with one tappable segment per scene (name from `label` or the narration's first words) and ⭐ markers.
- **LessonVideo fallbacks** (`planSources`): primary → the primary video if playable, else the lesson's explainer; "I didn't get it — explain it another way 🔄" → the alternate if playable, else the explainer again at 0.75× (autoplay). YouTube is playable only with a real id, online, and the IFrame API loading within 8 s (then `onFail` → next source); MP4 only when `mediaUrl(src)` resolves (a sibling `.vtt` becomes captions). Nothing playable → `onUnavailable()` and the card "Video not available right now — let's learn with cards! 🃏". YouTube runs on youtube-nocookie.com with `enablejsapi=1&rel=0&playsinline=1&start&end&cc_load_policy=1&controls=0`, a transparent shield over the iframe (no taps reach YouTube links) and the app's end screen at the clip's end.
- **Tests:** jsdom has no `speechSynthesis` → captions-only path; inject a fake `Narrator` to test narration. Use fake timers and `MotionGlobalConfig.skipAnimations = true` (see `ExplainerPlayer.test.tsx`).
